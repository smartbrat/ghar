## 2. The two families are NOT the same shape

**People Profiles are already templatized.** 13 pages generated by
`scripts/build-person-profiles.mjs` + `scripts/person-profile-data.mjs` via
`npm run build:people`, from one `render()`. Routes must exist in **both**
`vercel.json` and `serve.mjs`, and serve.mjs needs a restart.

They use `.pp-contact`, **not** the brand card. Measured: `#000000` on white,
21:1. No defect, and it does not read the `--contact-*` tokens. Do not
"unify" these two contact treatments without being asked; a person page is a
personal portfolio and deliberately does not borrow brand-microsite parts.

**Brand Profiles are not templatized.** 8 hand-maintained pages, roughly 197KB
each, every one carrying its own copy of the inline CSS. There is no
generator and no source file. That is the actual gap.

## 3. The contact card token contract (the important discovery)

`dist/brand-profile.min.css` is **hand-maintained**: no source, no build step,
despite living in `dist/` and being named `.min`. Edit it directly.

It loads in `<head>` **before** each page's inline `<style>`, but its selectors
are `body .bpr-…` (0-1-1), which beat a page rule `.bpr-…` (0-1-0). **This is
why page-level overrides silently lose.** Do not fight it with specificity or
`!important`. Use the tokens.

```
--contact-surface            card background      DEFAULT #faf7f2
--contact-ink                body text
--contact-ink-muted
--contact-eyebrow-color
--contact-border
--contact-divider
--contact-panel-bg           inset CTA panel
--contact-panel-border
--contact-panel-border-width
--contact-panel-radius
--contact-panel-padding
--contact-spine-width        0 disables the spine hairline
--contact-cta-bg
--contact-cta-fg
--contact-cta-hover-bg
--contact-cta-padding
--contact-cta-fontsize
--contact-glow-alpha
```

**The root defect: `--contact-surface` defaults to `#faf7f2`.** On a
white-ground page that is 1.07 contrast, so any tenant that declares nothing
gets a card that merges into the page.

## 4. Pending work

1. **The three undeclared tenants** (asian-paints, obeetee, saint-gobain) sit
   at 1.07. Either give each a token block, or change the default. Ask which:
   the user has said only Avirahi and Horizon looked wrong, so the other three
   may be considered acceptable and must not be changed on assumption.
2. **`_dev/templates/*.html` carry no contact tokens at all** (verified: 0
   occurrences in all 7). A new tenant built from a template therefore starts
   with the merging default. This is the single highest-value templatization
   fix: put the contract in the template.
3. **The token contract is undocumented** in the design system. Chapter 08
   (`#tpl-brand-profile`) describes accent, logo tiles and team photos but not
   this API. It should be there, or the next person overrides `background` and
   breaks the dark tenants exactly as happened in this thread.
4. **Changelog** has no entry for the brand-profile work in this thread.
5. Brand profiles have no generator. Whether to build one, mirroring
   `build-person-profiles.mjs`, is a decision for the user, not an assumption.

## 5. Two mistakes made in this thread. Do not repeat them.

**Going wide when asked to go narrow.** Asked about the contact card, I decided
the pages looked flat, invented a section-banding system, and pushed it into
the shared stylesheet, changing every section on all 8 templates. Reverted.

**Overriding a value a token system already owned.** After that revert I set
`background` directly on `body .bpr-contact__inner` in the shared sheet. That
bypassed `--contact-surface`, so Godrej and Scarlet Splendour got a pale card
while their `--contact-ink` stayed light: unreadable. The user caught it on
both pages. Reverted.

The lesson both times: **look at how a working tenant is styled before writing
any CSS.** Godrej and Scarlet already demonstrated the correct API. Five
minutes reading them would have avoided both rounds.

**Verification that works here:** load each tenant in an iframe, read
`getComputedStyle` for the card, walk up for the true ground, convert through
a 1x1 canvas to get sRGB out of `oklab()`/`color-mix()`, and compute the
contrast ratio. Never judge these by eye alone; `color-mix` and token
fallbacks resolve in ways that look plausible and measure wrong.
